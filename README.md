# lmhub-runner

Independent AI runner in Rust: models act as **coding agents** that receive a
public system prompt plus a controlled set of tools, and work inside their own
sandboxed workspace.

## Quick start

```bash
cargo run
```

The interactive TUI starts — no CLI flags:

1. **Setup** tab: pick a provider → models auto-load (source shown) → pick a
   model → reasoning level → system prompt (`d` sets the default) → type a
   task → `Enter` runs it.
2. **Run** tab: live events feed, tokens/cache/cost/tool-call counters,
   `c` cancels.
3. **History** tab: previous runs; `Enter` opens their `statistics.json`.

Providers need an API key in the environment: `OPENAI_API_KEY`,
`ANTHROPIC_API_KEY`, or the env var named in a custom provider's TOML.

Custom providers live in [`providers/`](providers/) as TOML files — see
[`providers/example.toml.example`](providers/example.toml.example). Adding one
requires **no changes to the runner core**.

System prompts are markdown files in `prompts/` (+ `~/.config/lmhub/prompts`);
`default.md` is materialized on first run.

## Output layout

Every run writes exactly this structure:

```text
output/
  {family}/            # e.g. Claude, GPT, GLM, DeepSeek…
    {model}/
      {reasoning}/     # off | low | medium | high
        {start}-{runid8}/   # unique per run — reruns never clobber
          output-modelu/    # ONLY files generated by the model
          statistics.json   # written for every terminal state the runner sees
          events.jsonl      # tool calls, LLM turns, errors, warnings
          errors.log        # human-readable error lines
```

## Sandbox

The model can only affect its `output-modelu/` directory:

- all file tools are jailed there (path canonicalization + prefix checks;
  `..` traversal rejected; symlink escapes detected);
- `run_command` executes only allowlisted commands (default `node`, `npm`,
  `npx`) resolved via PATH manually, passed as argv arrays — no shell;
- child processes get an empty environment (`PATH`/`HOME`/`TMPDIR` inside the
  workspace only), a per-command timeout, hard resource limits
  (address-space / CPU / file-size / process count / fd count), and the whole
  process group is killed on expiry (SIGTERM, then SIGKILL after a grace
  period);
- violations land in `errors.log` and `events.jsonl`;
- the runner never logs API keys or environment secrets (values are scrubbed).

Note: this is application-level sandboxing, not OS-level isolation (no
namespaces/seccomp). Run only with providers you trust accordingly.

## Model list & pricing provenance

Models resolve through a fallback chain, always labeled in the TUI:

1. **Provider API** (`/models`)
2. **Models.dev** (<https://models.dev/api.json>, cached in `~/.cache/lmhub`
   with a TTL; sha256 prefix recorded as snapshot version)
3. **Local provider config** (`[[models]]` in the custom TOML)

Prices come from Models.dev tied to the concrete provider+model route. If no
price exists, cost fields stay `null` and a warning is logged — never guessed.
Reasoning tokens are reported separately and never billed twice.

## Providers (the full opencode catalog)

The runner ships a bundled snapshot of **models.dev** — all 194 providers
opencode supports are available out of the box, routed through dedicated
adapters per protocol:

- OpenAI-compatible long tail (155+): groq, mistral, xai, perplexity,
  together, deepinfra, cerebras, openrouter, fireworks, …
- Native adapters: OpenAI, Anthropic, Google Gemini, Azure OpenAI,
  Amazon Bedrock (bearer + SigV4), Vertex AI (Gemini & Claude variants),
  Cohere, GitLab Duo, GitHub Copilot (device flow), watsonx/SAP pre-auth.

Credentials resolve from `~/.config/lmhub/auth.json` (TUI: pick provider →
`Enter`, type of key stored with 0600) or environment variables; local
runtimes (ollama, lmstudio, llama.cpp…) need none. The provider list is
filterable (`just type`) and shows `[key ok] / [no key] / [local]` badges.

Regenerate the catalog snapshot after models.dev updates:

```bash
cargo run -p xtask -- gen-providers
```

## Streaming & resilience

Model responses stream token-by-token (SSE) for OpenAI-compatible providers,
Anthropic (incl. Vertex-Anthropic), and Gemini (incl. Vertex-Gemini); the TUI
shows a live tail of the current turn plus a delta counter. Protocols without
SSE support (Bedrock, Cohere) transparently fall back to non-streaming —
`statistics.json`, `events.jsonl` and the tool protocol are identical in both
modes (streaming deltas are UI-only and never persisted).

### Reasoning levels

Models declare their supported reasoning levels via models.dev
`reasoning_options` (the same source opencode uses) — from a plain on/off
toggle up to explicit effort levels. The TUI only offers the levels a model
actually supports (`off / minimal / low / medium / high / xhigh / max`), and
the agent clamps the requested level before sending anything, logging a
warning when it had to adjust. Models with no declaration get all levels;
custom TOML models can pin theirs with `reasoning_levels = ["off", "high"]`.
Providers that reject a level at request time degrade once (without
reasoning) exactly as before.

Transient failures (429/5xx/connect/timeouts) retry automatically:
**6 attempts**, exponential backoff 0.5 s → 30 s cap with jitter, honoring
`Retry-After`. Retries never apply once stream bytes started flowing.
Tune in `~/.config/lmhub/config.toml`:

```toml
max_retries = 6
retry_base_ms = 500
retry_cap_ms = 30000
```

## CI

GitHub Actions on every push/PR: `cargo fmt --check`, `clippy -D warnings`,
full test suite (`--locked`), release build smoke — plus a monthly
models.dev snapshot-drift check. Tagging `v*` builds release binaries for
linux (x86_64, aarch64-musl) and macOS (x86_64, aarch64).

Regenerate the catalog snapshot after models.dev updates:

```bash
cargo run -p xtask -- gen-providers
```

## Configuration

`~/.config/lmhub/config.toml` (all optional). A broken file refuses to start
until fixed; zero/absurd values are clamped with a warning:

```toml
default_prompt = "default"
run_timeout_secs = 900
max_turns = 30
command_timeout_secs = 90
allowed_commands = ["node", "npm", "npx"]
modelsdev_ttl_secs = 86400
max_output_tokens = 16384
read_file_max_bytes = 48000
write_file_max_bytes = 1000000
```

Paths default to the project directory and OS config/cache dirs; every path
is overridable via environment: `LMHUB_CONFIG_DIR`, `LMHUB_CACHE_DIR`,
`LMHUB_OUTPUT_DIR`, `LMHUB_PROVIDERS_DIR`.

## Architecture

```text
crates/core        domain types, Provider trait, statistics schema, auth store
crates/modelsdev   catalog client + local cache + pricing lookup
crates/providers   native + routed adapters (194-provider catalog), model
                   resolution chain, SigV4/JWT/device-flow helpers
crates/sandbox     path jail, allowlisted process runner, the 7 tools
crates/agent       agent loop, event sink, cost computation
crates/tui         ratatui interface
xtask              `gen-providers` catalog snapshot regeneration
src/main.rs        wiring
```

Add a provider = implement `lmhub_core::Provider` (async-trait), drop a
TOML into `providers/`, or just set its env key — the catalog already knows it.
